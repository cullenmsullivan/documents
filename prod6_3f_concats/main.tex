\section{Introduction}
Iterating over full datasets ("the CAFs") is cumbersome for analysis. A "concat" is a reduced dataset where we only keep events passing a loose preselection ("decaffing") and removing branches we don't need ("reducing").
This document details the methods used to produce concats for the 3 flavor group.

The selections for the prod6 concats are more or less copied from prod5.1 \cite{ref:prod51_concats} except using the new ML vertexer, particle ID, and energy estimator where appropriate.

An analysis with full selections should be identical when prepared using CAFs and concats, so we include validation spectra demonstrating this for every concat.

This is an actively developing document and will be updated as the analysis progresses. Currently, we mostly have \texttt{v1} concats, indicating that selections are copied from prod5.1 with minimal edits and untuned for prod6. Datasets may not be final, and no file-based systematic variation concats are available.

\section{Preparing concats}
We use the "reducer macro" technique to prepare the concats. The macros that do this for Ana2027 are kept in \texttt{3Flavor\-Ana/\-Ana\-2027/\-reducer}. Many configuration files are kept in this area for submitting different types of concats, and we use Fermigrid to iterate over the CAFs. For example,
\begin{verbatim}
  submit_cafana.py -f reduce_ana27_numu_nonswap_fhc.cfg
\end{verbatim}
prepares FD FHC numu nonswap concats using the arguments in the configuration file. As of the \texttt{v1} run of concats, all job configurations output 100 files per concat definition. Output names of the files will be \texttt{CONCAT\_\-NAME.N\_\-of\_\-100.\-root} For each concat definition, once all jobs have been successfully received (potentially after draining) concats are moved off of PNFS scratch and onto PNFS persistent. On persistent, we make the SAM definition for the concats:
\begin{verbatim}
  ls *root > files.txt \# sam_add_dataset wants a list of files.
  sam_add_dataset -n <dataset name> -f files.txt
  rm files.txt
\end{verbatim}
If passed the raw filenames from the job output, \texttt{sam\_\-add\_\-dataset} will prepend some hash to each file before registering the file. It is also useful to generate the list of files under xrootd paths for the CAFAna dataset cache (either for everyone or for your personal cache at \texttt{\$CAFANA\_\-DATASET\_\-CACHE\_\-DIR}):
\begin{verbatim}
  samweb take-snapshot <dataset name>
  cache_state.py --list-cached --xrootd -ss latest -d <dataset name>
  mv cached.list <your cache directory>/<dataset name>.list
\end{verbatim}
The concat should now be queryable on SAM.

\section{Selections}
\subsection{FD numu selection}
FD numu selections require basic quality (\texttt{k\-Numu\-Basic\-Quality}). For \texttt{v1}, we use a copy of the 2024 version for FD containment except using the ML vertexer (\texttt{k\-Numu\-Contain\-FD2024\_\-Prod6}).
\todo[inline]{v2 of this concat should use tuned prod6 containment.}
FD numu selections also require loose cosmic rejection. Like for prod5.1, we require numu containment PID (\texttt{k\-Numu\-Cont\-PID}) to be greater than 0.4. Like in prod5.1, we also require the numu CVN score to be greater than 0, except for prod6 we use transformer CVN.

\subsection{FD nue selection}
FD nue selections require basic quality (using the ML vertexer) (\texttt{k\-Nue\-2024\-FD\-Basic\-Quality\_\-Prod6}).
\todo[inline]{v2 of this concat should use proper prod6 basic quality.}
Like in prod5.1, the nue CVN score is required to be greater than 0.5, except for prod6 we use transformer CVN.

\subsection{ND numu selection}
ND numu selections require basic quality (\texttt{k\-Numu\-Basic\-Quality}). For \texttt{v1}, we use a copy of the 2024 version for ND containment except using the ML vertexer (\texttt{k\-Numu\-Contain\-ND2024\_\-Prod6}).
\todo[inline]{v2 of this concat should use tuned prod6 containment.}

\subsection{ND nue selection}
ND nue concats include both nues and (un)contained numus because the numus are required for BEN decomp.

The nue selection requires basic reconstruction quality using the ML vertexer (\texttt{k\-Nue\-2024\-Reco\-Quality\_\-Prod6}), that the vertex is contained in the fiducial volume using the ML vertexer (\texttt{k\-Nue\-2024\-ND\-Fiducial\_\-Prod6}), and prongs are contained using the ML vertexer (\texttt{k\-Nue\-2024\-ND\-Contain\_\-Prod6}).

\todo[inline]{v2 of this concat should use proper prod6 reconstruction quality and containment cuts.}

Contained numus require basic quality (\texttt{k\-Numu\-Basic\-Quality}), either that the muon track is contained (\texttt{k\-Numu\-Contain\-ND}) or that all prongs are contained (\texttt{k\-Numu\-Contain\-ND\-2024\_\-Prod6}), and either REM ID being higher than 0.75 (\texttt{k\-Numu\-NC\-Rej}) or REM ID being higher than 0.30 and numu CVN score being higher than 0.76 (using the transformer score) (\texttt{k\-Numu\-2024\-PID\_\-Prod6}).

Uncontained numus have the same basic quality and PID requirements as contained numus. They also require failure of either \texttt{k\-Numu\-Contain\-ND}, \texttt{k\-Numu\-Contain\-ND\-2024\_\-Prod6}, or a BEN-specific cut, \texttt{k\-BEN\-Ka\-Numu\-Contain}, a cut that requires the start and stop of kalman tracks to be contained. The uncontained numus do require fiducial containment of the (ML) vertex and the kalman start and stop points (\texttt{k\-BEN\-Ka\-Numu\-Fiducial\_\-Prod6}).
